## rewrite-architecture

### Summary

The rewrite (branch re-write, HEAD 5c21aaaf, ~13.1k non-test lines, 485/485 tests green) is a genuine clean-room reimplementation whose lower layers honor the .reimplementation contract well: the pure Zod domain spine (single-pass evaluate producing overlay+rows, branch-scoped recompute, unified rows[], fixed clamp-visibility), the 12-state popup FSM with a frozen per-state memory matrix (incl. the editor_preparing exemption), one typed bus with idempotent-by-sequence replies, a real nonce-armed single page-world program, token rotation on every authed call, backend-issued lock identity, and a well-reasoned backend-authoritative local-data rule. But the authority model is inverted at the top: the 1,800-line popup entrypoint (src/entrypoints/popup/main.tsx, ~45 module-level mutable variables grown over the last ~15 commits) is the de-facto orchestrator. It births 12 of 16 signal names via signals.emit (bypassing fold→decide, so the brain's run/preview/save/reconciliation deciders are dead code in the live path), composes and dictates the content organ's curtain/banner surface on a 500ms poll, keeps a shadow state bag (preLockPopupState + hand-built FSM states), re-derives session truth from content status, and even fabricates source:"brain" signals offline — the legacy dictation-model/dual-bag disease re-growing in a new host, though confined to one file with clean seams underneath. Signal delivery is pull-only (push channel never emitted; server-side consumed-once cursor implemented but unused; content consumes no signals at all — it is driven by popup-composed directives). Persistence is write-only: durable facts are persisted on every observe but never rehydrated, so an MV3 SW restart resets the per-tab seq to 0 while the popup's cursor survives, silently starving the popup of signals. Contract-critical gaps: /save posts a single-page snapshot and discards the response (destructive-save hazard if the owned backend does full-replace, INV-6.5); static render mode cannot produce a valid submission (schema demands rawHtml iff static, but no static-HTML fetcher exists — Run AI always fails on static properties); discard resets to defaults-only, not defaults+AI-selectors (INV-6.6); the INV-6.4 two-gate AI machinery is dead code; the lock lifecycle is popup-tethered (heartbeats only while the popup polls; no reconnect/probes/off-candidate/cooldown/tab-close release); preview is a stub. Verdict: vertical entanglement (god-file fusion) is solved; horizontal entanglement (who decides/owns/moves) migrated into the popup instead of the brain — better than legacy, but not the reflex arc, and trending the wrong way.

- The popup entrypoint src/entrypoints/popup/main.tsx (1,800 lines, ~45 module-level lets) is the system's real orchestrator: it emits 12 of 16 signal names itself via signals.emit with source:'popup' (run.*, session.saved/discarded, preview.opened, reconciliation.*, marking.enabled/disabled), bypassing the brain's fold→decide loop entirely (rewrite-brain.ts:24-37 emitSourceSignal appends without folding)

- The popup composes the content organ's full curtain/banner/blocked surface (composeContentDirective, main.tsx:675-708) and pushes it to content on every 500ms poll tick — the retired 'dictation model' relocated from background to popup; content consumes zero brain signals and is driven purely by commands/directives

## legacy-arch-weaknesses

### Summary

Cataloged 49 testable weaknesses (W-01..W-49) of legacy Unfluffify v1.10.0, each with file:line evidence, the bug it caused, and the correct-design counterpart, plus a 25-row rewrite acceptance checklist. The system runs nine parallel transports (88 raw message-type strings beside a typed bus, ports, a page-world relay, a TTL'd payload store, CDP, and an offscreen doc) dispatched through a 47-branch if-chain in background.ts. Decisions are multi-owner everywhere: marking-enabled derives from five competing sources in a ~1,914-line non-serialized refreshUiInner whose interleaved passes required four hand-maintained guard systems (epochs, seq stamps, raise-only latches, source-omission heuristics); AI-run authority is negotiated by a five-field pattern match; popup presentation is a three-layer override sandwich. State is flat mutable singletons (~180 popup fields, 112 content fields), a whole-map read-modify-write config store written by three realms with per-context-only queues, five coexisting per-tab background stores with divergent lifetimes (the direct cause of the MV3 stuck-spinner bug), and sticky level-snapshots re-folded by a 1 Hz heartbeat where one forgotten republish wedges the system permanently. Save integrity is the gravest area: /save is a full-snapshot replace behind a coverage filter that emitted pageMarkings:{} and wiped a production property on a 200 response — the guard fix exists only as dangling commit e11059b1, not on main; AI-computed selectors are persisted only by the popup on the happy path and the resume path deletes the run record on any hiccup, matching the observed intermittent selector loss. Lifecycle bugs include the reveal ritual latch consumed on attempt rather than success, brain.disposeTab documented known-unsafe for navigation, popup-dependent content activation, and a render-mode inspection saga with no durable record that leaves deleted-record properties un-bootstrappable. Error handling swallows causes into {ok:false} (73 bare catches in background.ts alone) behind generic toasts like "Unable to save session", which is why the data wipe looked like a successful save. 77 of 202 test files pin source text with regexes instead of behavior, and core flows are verifiable only through documented-flaky live CDP harnesses.

### Key findings

- Production data loss is structural, not incidental: /save full-snapshot replace + coverage filter keyed on a best-effort backend-saved cache emitted pageMarkings:{} and wiped a property on HTTP 200 (remote-config.ts:420-445); the guard exists only as dangling commit e11059b1 — production main today has no protection.
- AI selector persistence has a single fragile writer: only popup applyComputedSelectorSet (popup.ts:8396) writes config.selectors, after the run roundtrip resolves in the popup; popup closure loses the result and the resume path (popup.ts:6370-6470) deletes the persisted run record on any status hiccup — the mechanism behind the observed intermittent selector loss.
- Marking-enabled has five competing sources reconciled inside the ~1,914-line non-serialized refreshUiInner (popup.ts:5106-5226), including a content probe whose conclusion the popup writes back into background tab state; the documented #5/#14 session-collapse family and the epoch/seq/latch guard doctrine all exist to defend against this one function's interleaving.
- Coordination is level-triggered and sticky: popup/content accumulate merged fact snapshots re-pulled by a 1 Hz brain heartbeat (heartbeat.ts:46-51), so any teardown that forgets to republish a fact leaves it re-folded forever (knowledge.md:603); the store also schedules a projection on every mutate including no-op folds, and the resulting publish->fold->project->apply loop (~200/sec) was patched with a dedup cache rather than removed.
- One-shot lifecycle latches are consumed on ATTEMPT, not success: consumePageVisitRevealFreezeAttempt (content-main.ts:2180-2189) permanently blocks the reveal/freeze ritual for a page visit after any early failure — the exact bug the rewrite's 'let the ritual survive an early attempt' commit fixes.
- brain.disposeTab is documented known-unsafe for navigation (deletes popupPortCounts, corrupting fact-source arbitration while the popup stays connected — brain/index.ts:1007-1017, knowledge.md:552); navigation teardown is instead spread across four uncoordinated handlers with different definitions of 'navigated'.
- The config store is whole-map read-modify-write from three realms (popup, content, background all call updateConfig/saveConfigs) serialized only per-JS-context (config.ts:35-36), and getConfigs writes back during reads — cross-realm lost updates are structurally possible.
- MV3 restart-safety is achieved by hacks: a refcounted 20s keepalive, a 30s spinner expiry grace projecting away stuck curtains caused by the queue-in-memory/selection-persisted split (spinner-authority.ts:22-49), and session-storage brain state that resurrects stale preview-open wedges across SW reloads (knowledge.md:608).
- Legacy mobile emulation spoofs device metrics only via chrome.debugger (emulation.ts:330-376) — no user-agent/client-hints identity — so UA-sniffing sites serve desktop DOM into the mobile viewport and saved snapshots inherit the hybrid.
- Error handling masks causes end-to-end: 73 bare .catch(() => {ok:false}) handlers in background.ts, replyWithKeepAlive maps any failure to a fallback with no log, and the user-facing surface is generic text ('Unable to save session', text.ts:438) — why the production wipe presented as a successful save.
- Testability is inverted: 77 of 202 test files readFileSync production source and assert regexes over it (source-contract pins), while real behavioral verification requires documented-flaky live CDP harnesses with trusted-input, dialog-safety, and SW-cache pitfalls filling the knowledge base.
- Four god files hold 57% of the source (core.ts 14,312 / popup.ts 10,003 / content-main.ts 7,557 / background.ts 4,301 lines) and core.ts is formally edit-frozen without an approved plan; business predicates are duplicated across bundles and kept equal by comments and byte-identity tests (the eval'd page-motion freeze pair).

### Open questions raised

- Should /save remain a full-snapshot-replace API (requiring client-side destructive-write guards), or should the backend move to keyed per-page/delta writes? The wipe class is only fully closable server-side.
- What is the intended recovery UX for a property whose backend config record was deleted mid-lifecycle: silent auto-recreation from local state, or an explicit re-onboarding flow (render-mode re-inspection required)?
- Should the content engine (consent hiding + reveal/freeze + silent highlights) run on EVERY configured property page at load for every editor, accepting the page-load performance cost, or only on popup-engaged tabs? Legacy broadened this in Round 3 with an explicitly flagged unvalidated perf risk.
- When an AI run completes after the popup has closed, should the background persist and surface the result on next popup open (and should the user be charged/notified for runs whose results were auto-persisted without review)?
- Is the 'marking never survives navigation/reload' contract desired product behavior, or should an accidental same-URL reload resume the marking session with its unsaved draft?
- How deep should mobile identity spoofing go (UA string only, full UA-CH, touch/pointer media, platform hints)? The target definition — e.g. Googlebot-smartphone parity — determines both implementation and what the saved snapshots represent.
- Should destructive confirmations (discard, transfer, cache clear) remain native blocking dialogs or move to non-blocking in-popup UI? Legacy's window.confirm calls freeze the fact pipeline and break automation, but native dialogs are the established editor UX.
